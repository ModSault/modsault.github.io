Information About The Tool

How to use the Tool

  • This tool requires you to have already extracted your game files from Star Fox Assault. If you haven't done so and don't know how, you can follow my guide here.
  • .nut Files Overview - These are container files for multiple texture files at once. A file can contain hundreds of textures. This tool allows you to view and edit all the textures they contain.
  • Uploading Files - Below this box is a dashed upload area. Either click on it and select the file you want on your pc, or drag and drop the file of interest into that area. This will load the file and all of its contents.
  • Left side of this tool - Right below where you upload your .nut files is a quick overview of all textures within the file. You have the ability to remove, add, and view all textures from here.
    • [WWWWWWWW] Texture #X (Y - ZZxUU) - This is one texture within the entire container file. Clicking on it displays all information regarding the texture with explanations. WWWWWWWW is the texture ID that the game uses to identify the texture. X is the texture's position in the container, starting at 1. Y is the number of mipmaps or palettes, and ZZ and UU are the texture's width and height, respectively. An indented entry indicates that "Only Save Color Information" is checked for the file.
    • - (Advanced mode only) This reorders the textures in the container. This moves the texture up by 1.
    • - (Advanced mode only) This reorders the textures in the container. This moves the texture down by 1.
    • - The texture is not currently displayed in the preview. Click to show it.
    • - The texture is currently displayed in the preview. Click to hide it.
    • - This downloads all mipmaps and palettes for the selected texture in a ZIP archive.
    • - This permanently deletes the texture from the container file.
    • File Header Data (Texture Settings) - (Only visible when expanding the textures contents by clicking on it) This displays the texture's metadata, such as its dimensions and compression format. All options and values are explained there.
    • Pixels - (Only visible when expanding the textures contents by clicking on it) This displays all rgba values of all pixels in the image. Pixel IDs start at 0 in the top-left corner and increase from left to right, moving down one row at a time. It also displays the value of the compressed image you'll see in game.
    • Colors - (Advanced mode only. Only visible when expanding the textures contents by clicking on it) This displays all colors found in the file if not embedded in the pixels. This does nothing aside from providing you with more information about the file.
  • Right side of this tool - On the right half of the screen (or below the above contents if your screen is too small) is a preview of all of the texture's content in a more user friendly presentation.
    • The User's Image - This is the image you can freely modify. If you uploaded a game file then it is also the texture within the file.
    • Compressed Image - This is the image you will see in the game when exporting the file. You cannot edit it. The selected compression algorithm can change the image's appearance, so it may not look exactly like the editable "user" image.
    • Show Texture Settings and Compression - This allows for changing information about the image, like the width, height, and compression. It's recommended to use the left side of the screen to edit this information because it also contains explanations.
    • Show Image Display Settings - This allows for changing how you preview the image. Including the background of transparent images, the size of the mipmaps and whether to view the whole image or individual grids, the colors of pixels highlighted and selected, and the scroll speed.
    • - Use the arrows to switch between textures or cycle through a texture's mipmaps/palettes. Clicking an arrow outside the white glow switches textures; clicking inside the glow switches mipmaps/palettes. You can also navigate using WASD, Q/E, and the arrow keys. Holding any of these scrolls through the textures
    • Buttons at the Bottom - These allow you to download the texture, upload another one (ensure the image sizes match), or set all rgba channels of the texture to 0 respectively.
  • Exporting - At the very bottom of the page there is a dropdown to select the filename to download. Select the appropriate file name and then click the big blue button.
  • File Preview - (Advanced mode only) Allows you to see all information regarding the file you will download along with explanations for what each offset means. Recommended for debugging and learning.

What games does this tool work on?

This is meant for Star Fox Assault. If it happens to work for another game then that's a coincidence. This tool was made by observing how the '.nut' files are used in Star Fox Assault and designing it around that. If it turns out there is a feature/value in the these files that is supported by Star Fox Assault and I missed it, let me know. If implementing it isn't too difficult I'd be down for its addition.

Alternative Tools

There is a tool called Rainbow (Download). It can't export '.nut' files and doesn't read all of them perfectly, but is 99% functional for viewing them and could be useful in case this tool and the game disagree somewhere.

How do I edit the images.

You could manually write the red, green, blue, and alpha channels for all pixels you want to change in this tool. But let's be real here, don't do that. Download the image as a PNG, and use your preferred tool (like Photopea) to modify the image. Use whatever you want, as long as it exports PNGs then you're good. Just upload it to the site and it'll take care of the rest (assuming the image size is the same).

I changed a file but nothing happened in game

Not all of these files are read by the game so its possible you changed a file thats never used by the game. If your playing singleplayer than thats also a problem. They load everything they need inside of the '.fpc' files and not the '.nut' files.

What do half of these settings mean?

Expand a file's information on the left half of the screen and explanations will appear for everything. I hope they help you understand what's happening.

What is this grid thing?

Due to either how the game is coded or how the GameCube's GPU works, it expects the data for a texture to written in a certain way. Part of this is rendering rectangular parts of the image at a time. So these rectangular segments of the image are rendered in order from the top left, then to the right, and then down until it reaches the bottom right. Each grid represents one of these rectangles that the game renders at a time. The only exceptions is the blend compression algorithm which does it in larger 8x8 rectangles, but also does the same thing for the 4 smaller 4x4 rectangles inside of the 8x8 rectangles. You cannot change the image size to not be divisible by the grid size of the current compression algorithm.

The website froze/feels slow

Can't say I'm surprised. This isn't optimized. For example changing one pixel recompresses the entire thing which is slow (duh). If you think there is a bigger problem open devtools (right click + inspect) and find the console tab. If something red appears report it.

Blend Compression is Flawed

I'm aware of this. Encoding a file with the blend compression type will make the image differ from what the game file had by some slight amount. Unfortunately I'm not an expert on image compression and I barely understand how the encoding works in the first place. The current encoding algorithm only exists because of AI and because the problem is hard to see with the naked eye I dismissed it.

Why Can't I have mipmaps and different Palettes?

I didn't know that different palettes in the same texture could exist until I was like 99% done with this tool. So instead of redesigning all the systems for it I just did a half fix where if a compression type supports different palettes it doesn't support mip maps. The game never uses both at once so I didn't think it was too important to account for and I want to move onto other projects.

How to report bugs

I have a small audience so doing anything would get my attention. Using GitHub issues would be best but even a Reddit DM would work if you really wanted to (assuming I get an email).

Allow Unique Character Textures [ModSault]

Normally the textures for the Vs. Mode characters share data with each other making entirely unique textures for each player impossible. This code allows all 4 colored player textures to be treated as entirely different. Just make sure to open the appropriate file for the characters you have selected below and redownload it except with "Only Save Color Information" disabled on all textures.

File Preview

General Information

  • This is the file you will download upon clicking the button above. This is shown to you to make debugging easier and document the file structure. If you uploaded a file this won't match that. However you can read the descriptions at each offset to understand the original file.
  • The reason there are no addresses here is because after the file is loaded it extracts the data from it and places it somewhere else.
  • The Textures are also sorted into a binary tree with a key and a value. The key being the texture ID, and the value being a small data structure that has all info for the file, including pointers to the copied data from the file.
  • The pixel data and color data are in their own binary trees. Both binary trees are very similar in functionality.
  • The colors shown in the preview section are arbitrary picks by me. But generally if something isn't colored than its constant no matter what you do to a texture. The alternating colors in the pixel and color section are just there so you can easily tell which pixels and colors are a part of the same grid or palette respectively.
